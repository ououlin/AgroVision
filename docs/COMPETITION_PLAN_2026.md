## 1. 结论与定位

AgroVision 具备参赛基础，但不能只按“AI 拍照识别 App”提交。比赛强调公共数据与社会数据融合、数据要素价值释放、实际问题解决和面向东盟的应用价值。参赛定位调整为：

**项目名：农智眼：面向中国-东盟小农户的多源农业数据融合与病虫害智能决策平台**

**一句话价值：** 融合公共气象、农技知识、农药安全信息与农户田间记录，在弱网环境中完成风险预警、图像识别、处置建议和用药留痕，为小农户减损和跨境农产品质量安全提供可追溯的数据链。

AI 识别是平台中的一个算法能力，核心参赛叙事是：

```text
多源数据采集 -> 来源登记与治理 -> 场景融合 -> 风险判断与问诊
-> 农户行动 -> 用药/复查留痕 -> 结果反馈 -> 数据与模型持续改进
```

### 3.1 现有可演示能力

- 首页按农户任务组织，主流程为拍照问诊。
- 当前随包模型可离线运行，但 ONNX 图真实输出只有 8 类，只能作为流程试验模型。
- 问诊结果按“今天先做、原因、用药参考、复查、安全提醒”输出。
- 地块、历史、用药、安全间隔期和采收提醒形成结构化记录。
- 问农技支持日常对话、多轮上下文、诊断上下文和离线基础回答。
- 本地知识检索、物候规则和天气风险规则不依赖 LLM。
- 隐私同意门槛、原图默认不上传、手动备份已经落地。

### 3.2 答辩中必须如实说明的限制

- 当前模型仅有 8 个分类输出；39 项标签目录和百科覆盖不等于模型覆盖。
- `pest_detector.onnx` 未随包，不能演示或宣称害虫检测头已经发布。
- 和风天气和 wttr.in 不是政府开放数据，不能作为“政府数据融合”的证据。
- 文档中的目标值和历史示例不是实测指标。
- 账号、云同步、GIS、OCR、巡检、机器人和多智能体实验模块均不计入当前作品能力。

## 4. 目标用户与东盟场景

### 4.1 核心用户

| 用户 | 关键痛点 | 产品回应 |
|---|---|---|
| 广西小农户 | 不会判断病害、弱网、用药记录零散、专业术语难懂 | 离线识别、行动式结果、语义简单、拍照即用 |
| 农技员/合作社技术员 | 服务半径大、重复问诊、缺连续记录 | 地块时间线、问诊与复查记录、统一数据摘要 |
| 产销合作社/跨境供应链人员 | 难核对处置过程和采收安全时间 | 用药与安全间隔期摘要、可追溯记录、双语摘要目标 |

### 4.2 推荐落地场景

聚焦“广西特色农产品生产端病害减损与跨境质量安全协同”，不把项目扩张成完整跨境贸易平台。用一个真实可演示闭环支撑东盟价值：

1. 广西种植户建立柑橘或番茄地块。
2. 公共气象/预警数据与地块物候融合，生成风险提醒。
3. 农户拍照，设备本地给出候选和处置建议。
4. 农户记录实际用药与安全间隔期。
5. 复查结果回流，形成“输入数据-判断-行动-效果”记录。
6. 导出中英双语农事安全摘要，供合作社或跨境采购沟通。

双语摘要是决赛增强项，不等于产品取得质量认证，也不能替代法定农残检测。

## 5. 数据要素方案

### 5.1 数据分层

| 层级 | 数据 | 用途 |
|---|---|---|
| 政府/公共数据 | 广西开放数据、气象公开数据、农药登记公开信息、东盟宏观统计 | 区域风险、规则校验、场景规模和价值论证 |
| 开源科研数据 | PlantVillage；后续候选 IP102 | 模型训练与基准测试 |
| 农户生产数据 | 地块、作物、物候、图片、问诊、用药、复查 | 个性化决策与过程追溯 |
| 模型衍生数据 | Top-3、置信度、风险等级、规则命中、建议 | 决策支持与效果分析 |

详细许可和接入状态以 `docs/DATA_PROVENANCE.md` 为准。

### 5.2 治理要求

- 建立统一 `source_id`，每条派生数据可回溯发布机构、版本、获取日期和 SHA-256。
- 原始快照只读保存，清洗、标准化和特征生成均由脚本执行。
- 训练/验证/测试按文件清单固化，做精确与感知哈希去重。
- 农户原图默认不出端；用于比赛测试集时单独授权、去 EXIF、脱敏。
- 建议结果记录模型版本、规则版本和输入数据版本，保证复盘可解释。

## 6. 比赛版功能范围

### P0：初赛前必须完成

| 工作包 | 交付物 | 验收标准 |
|---|---|---|
| DATA-01 公共数据接入 | 至少 1 个广西或国家政府开放数据快照、导入脚本、字段映射、许可说明 | App 或测试程序真实使用；断网可用冻结快照；材料可复现 |
| DATA-02 数据台账 | 数据清单、字段字典、血缘图、SHA-256、脱敏说明 | 每个已用数据有来源和处理记录 |
| MODEL-01 正式基准 | 独立测试集、去重报告、Top-1/Top-3、Macro-F1、分类别指标、混淆矩阵、ECE | 数字均由脚本生成并留原始文件；不使用 mAP 描述分类头 |
| PERF-01 真机性能 | 至少 2 档 Android 设备的 p50/p95 时延、峰值内存、包体、100 次稳定性 | 保存设备型号、系统、日志和原始 CSV |
| PRODUCT-01 数据闭环 | 地块-问诊-用药-复查可连续演示，结果显示数据/模型来源 | 2 分钟内稳定完成，无网络仍能走核心流程 |
| USER-01 场景验证 | 5 名农户、2 名农技员、1 名合作社/产销人员的访谈和任务测试 | 有原始问题、同意记录、结论和整改前后对比 |
| DELIVERY-01 提交包 | 源码、模型、测试程序、数据集、PDF、环境、2 分钟视频 | 按官方命名自检两遍，8 月 25 日中午前完成上传 |

- 中英双语农事安全摘要，明确“辅助记录，非检测证明”。

- 典型广西作物完整演示数据和 3 个真实案例。
- 5 分钟 PPT、离线演示包、录屏备份和 20 个高频问答。

### P2：本届比赛不作为承诺

- 不开放未部署的账号/云同步。
- 不展示 GIS、机器人、多智能体大屏等实验代码。
- 不做全量多语言 UI；先保证核心摘要准确。

## 11. 风险与红线

| 风险 | 处理 |
|---|---|
| 把目标值或示例值当实测 | 所有数字必须能定位到原始 CSV/日志/脚本；否则写“待测试” |
| 公共数据叙事空心化 | 至少一个政府开放数据真实进入规则或展示链路，不只放在 PPT |
| 东盟标签生硬 | 用跨境质量安全协同和双语记录解决真实沟通问题，不堆“东盟”字样 |
| PlantVillage 实验室背景泛化差 | 增加真实田间独立测试集，分开报告域内与域外效果 |
| 功能过多导致演示失败 | 比赛版只保留一条 2 分钟稳定闭环，实验功能继续关闭 |
| 用药建议造成安全风险 | 以登记信息和标签为准，展示来源、适用范围和安全提示，不生成确定性处方 |
| 官网时间冲突 | 以最新盖章调整通知为准，9 月 16 日前完成决赛提交 |

## 12. 完成定义

- 报名已审核，团队信息无误。

- PDF 测试报告覆盖官方七章，所有图表可追溯。
